# Why Ligase works this way

<Lede>
These pages explain the reasoning rather than the usage. Nothing here is needed
to run a pipeline — [the guides](/guide/) are for that — but everything here is
needed to predict what Ligase will refuse, and why.
</Lede>

The one idea underneath all of it: biological data carries **dimensions** —
organism, reference build, coordinate system, sample set — and connecting two
steps whose dimensions disagree is the shape of nearly every silent failure in
computational biology. Ligase puts those dimensions in the type system, where a
mismatch is a build error rather than a plausible number.

## Dimensions beyond the genome

Each of these is a dimension that earned its place because its mismatch is a
documented silent failure, not because the file format was convenient to parse.

- [Identifier spaces](/concepts/identifiers/) — why the space a gene list's
  names live in is a dimension, and why there is no alias table.
- [Assembled data](/concepts/knowledge-graphs/) — why the evidence sources a
  knowledge graph was built from are a dimension, read off the graph rather
  than asked for.
- [What a molecule's name means](/concepts/molecules/) — why two compound sets
  standardised differently are two different sets of names for the same
  substances.
- [Where the data came from](/concepts/remotes/) — the fetch at the top of
  nearly every pipeline, pinned or recorded, and replayable either way.
- [Recording a live answer](/concepts/record-and-replay/) — what a recorded
  query promises that a live one cannot.
